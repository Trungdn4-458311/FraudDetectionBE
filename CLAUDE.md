# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A university **Business Analytics group project**: end-to-end payment fraud detection on the **PaySim** dataset (~6.36M mobile-money transactions) plus 9 synthetically-generated contextual features (Faker). The primary artifact is a single Jupyter notebook, `fraud_eda.ipynb`, structured as Modules 1–6 (Business Understanding → EDA → Cleaning → Feature Engineering → Modeling → Deployment). Notebook prose, comments, and print output are in **Vietnamese** — keep new content Vietnamese to match.

Grading rewards *rigor and honest interpretation* over raw accuracy; academic rules require code to be authored by the team, so **do not add AI co-author trailers to commits**.

## Data

- `PS_20174392719_1491204439457_log.csv` (~493 MB, the Kaggle PaySim base) is **git-ignored** (exceeds GitHub's 100 MB limit). It must exist locally for the notebook to run; download from the Kaggle "Online Payments Fraud Detection Dataset".
- `data_dictionary.{md,csv,xlsx}` document the 9 synthetic fields; they are regenerated by a notebook cell in Module 1.

## Running the notebook

- Always **Restart & Run All** top-to-bottom. State is carried in a single mutable `df`: Module 1 loads/merges synthetic features, Module 2.5 adds `errorBalance*`, Module 3 drops rows in place, Module 4.1 sorts `df` and adds velocity features. Running cells out of order breaks downstream cells (`NameError`, stale columns).
- Heavy: loads a 470 MB CSV and trains 6 models (2× LogReg, 2× RandomForest, 2× XGBoost) on ~1.9M training rows. XGBoost/RF cells take minutes; this is normal, not a hang.
- Requires `xgboost` in the kernel (not always present in a base conda env).

## Editing the notebook programmatically

Cells are edited by manipulating the notebook JSON with Python (not by hand), because outputs and Vietnamese text make manual edits fragile. On Windows the default stdout is cp1252, so **every Python invocation that prints Vietnamese must set `PYTHONIOENCODING=utf-8`**, and JSON must be written with `ensure_ascii=False`. Anchor edits by searching cell source substrings rather than fixed indices (indices shift as cells are inserted). Validate afterward with `nbformat.validate(...)` and ensure every cell has an `id`.

## Deployment (`deployment/`)

Serves the model as a real-time API + analyst UI. Structure:
- `scoring.py` — shared core: `featurize()` turns a raw transaction (type + amount + 4 balances) into the model's feature row, computing `errorBalance*` and `type_TRANSFER` server-side; `score_txn()` returns probability + decision. Loads `model.joblib`; the path is overridable via the `MODEL_PATH` env var (used for testing with a stand-in model).
- `api.py` — FastAPI (`/predict`, `/health`), imports `scoring`.
- `app.py` — Streamlit review-queue demo, imports `scoring`.
- `model.joblib` — a bundle `{model, features, threshold, model_name}` **generated by the notebook's Module 6 export cell**, not committed by hand. The served model is **XGBoost Base** trained on a reduced 8-feature set (drops `step` and the velocity/time features, which need account history and are near-useless on PaySim anyway).

```bash
# in deployment/  (after running the notebook's Module 6 cell to create model.joblib)
pip install -r requirements.txt
uvicorn api:app --reload      # API + docs at /docs
streamlit run app.py          # analyst review queue
```

`README.md` in `deployment/` carries the Hugging Face Spaces YAML header (SDK: streamlit); deploying = pushing that folder to a Space.

## Core modeling design (the important architecture)

The 9 synthetic features (`is_new_device`, `*_mismatch`, `account_age_days`, …) are **generated conditioned on `isFraud`** (Module 1, cell ~7: `p = where(fraud, ...)`), so using them naively **leaks the label**. The notebook handles this by building two feature spaces and comparing them everywhere:
- **Base** = real PaySim transaction features + engineered real signals (balance errors, velocity). No leakage.
- **Full** = Base + the synthetic risk signals.

Every algorithm is trained on both; Module 5.3 discusses the leakage and frames Full's uplift as an optimistic upper bound. Preserve this Base/Full split and the leakage framing in any modeling change — it is the intellectual core the grading looks for.

Facts worth keeping consistent when writing/reporting:
- Fraud only occurs in `TRANSFER` and `CASH_OUT`; Module 4 filters to these (positive rate rises 0.129% → 0.296%).
- Near-perfect scores (e.g. RandomForest Base PR-AUC 0.997, 1 false positive) reflect PaySim being *nearly separable by design*, not model brilliance — always report this as a limitation.
- **RandomForest Base** is the best honest model on metrics; **XGBoost Base** is what gets deployed (compact, fast, no leakage). Class imbalance is handled with class weights / `scale_pos_weight` (not resampling). The operating threshold (~0.21) is chosen by minimizing a cost metric (missed-fraud amount + `COST_FP=10` per false alarm) in Module 5.4.

## Verification

There is no test suite. Changes are verified with throwaway scripts that build a small synthetic DataFrame with the same columns and either `exec()` the relevant saved cell sources or replicate their logic — substituting a scikit-learn stand-in for `XGBClassifier` when `xgboost` is absent. Prefer this over running the full notebook when checking that edited cells are syntactically and logically sound.
